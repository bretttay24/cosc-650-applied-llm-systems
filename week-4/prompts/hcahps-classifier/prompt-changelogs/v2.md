## v2 (09-20-2026)

**Changed:** Added tool-use guidance that distinguishes complete ledger summaries from focused guarded statistics. The prompt now directs the model to use `get_summary` for complete label or confidence breakdowns and `run_guarded_summary_statistic` for one focused total, most-common-label, or percentage calculation.

**Reason:** During the Part 4 failure test, a request containing both a HCAHPS patient survey comment that needs classified and a request for a high-confidence percentage caused the model to call `run_guarded_summary_statistic` before `record_classification`. The returned percentage excluded the new comment, and the final response omitted the requested statistic. I first revised the guarded-statistic tool description to require recording all comments before calculating a statistic. When that change did not consistently correct the call order, I added explicit sequencing guidance to the system prompt.

**Impact:** Expected to improve multi-step tool-call behavior by directing the model to record the new classification before running a focused ledger statistic and to preserve all requested tasks in its final answer. Classification label definitions and model settings were unchanged. The guarded-statistic tool description was also revised during recovery testing.

**Eval:** This version was not evaluated with a full test suite. It was tested against the Part 4 failure prompt, which combines a patient-comment classification with a request for the percentage of high-confidence predictions. The recovery test should run the same prompt three to four times and verify that `record_classification` occurs before `run_guarded_summary_statistic`, and that the final answer reports both the classification and the updated percentage.
